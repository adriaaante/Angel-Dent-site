# Договоры, счета и акты по клиникам — как это работает

Тот же порядок, что заведён по ТПК «Сферикс», только автоматизированный:
один источник правды (`registry.json`) + генератор (`build-docs.py`) →
готовые `.docx` в `out/` → загрузка в Google Drive.

Папка **не деплоится** на сайт (весь `_materials/` исключён из rsync).

## Нумерация

Сквозная по ИП и **общая со Сфериксом** — так и должно быть: у ИП одна
книга учёта, две параллельные нумерации налоговую смущают.

- `counters.doc_no` — договоры и счета в одной последовательности.
  Занято: 1544, 1545, 1546 (Сферикс), 1547 (договор + первый счёт клиник).
- `counters.act_no` — акты. Занято: 1, 2 (Сферикс), 3 (ретро-акт клиник).

Счёт по договору № N выставляется под тем же номером N (как у Сферикса:
договор 1545 → счёт 1545), последующие счета по нему берут следующие
свободные номера.

## Команды

```bash
cd _materials/docs
pip install python-docx          # один раз

# ежемесячный счёт — самая частая операция
python3 build-docs.py invoice --month "сентябрь 2026"

# счёт на другую сумму / частичную оплату / задним числом
python3 build-docs.py invoice --month "сентябрь 2026" --amount 45000 --partial
python3 build-docs.py invoice --month "сентябрь 2026" --date 2026-09-01

# акт по итогам месяца
python3 build-docs.py act --month "сентябрь 2026" \
        --paid-by "счёта № 1548 от 01.09.2026 г."

# договор + приложение № 1 (после правки registry.json)
python3 build-docs.py contract

# соглашение о расторжении прежнего договора + акт сверки
python3 build-docs.py termination

# весь стартовый пакет разом
python3 build-docs.py all --month "август 2026"
```

Каждый запуск дописывает документ в `registry.json` → `documents`. Это и
есть реестр выставленного: что, когда, на какую сумму. Дублей нет —
повторная генерация того же номера перезаписывает запись.

## Порядок для бухгалтерии клиники и для налоговой

На каждый расчётный месяц должен быть комплект:

1. **Счёт** — выставляется в начале месяца, оплата 100 % предоплатой
   (п. 3.2 договора).
2. **Платёж** — приходит на р/с ИП в Т-Банке.
3. **Акт сдачи-приёмки** — по итогам месяца, подписывается обеими
   сторонами. Именно акт, а не счёт, подтверждает факт оказания услуги:
   счёт первичным документом не является.

Акт содержит все обязательные реквизиты первичного документа по ч. 2
ст. 9 Федерального закона от 06.12.2011 № 402-ФЗ: наименование и дату
документа, обе стороны, содержание факта хозяйственной жизни, величину
измерения с указанием единиц, должности и подписи.

Скан-копии по электронной почте признаются сторонами (п. 10.2 договора),
но **оригиналы лучше собирать раз в квартал** — при выездной проверке
запрашивают именно их.

## Соглашение о расторжении — подписывать только если было что расторгать

Прежний письменный договор с клиникой в Drive не найден. Если его
действительно **не существовало** (работа шла по устной договорённости и
счетам) — соглашение о расторжении **не подписывать вовсе**: нельзя
расторгнуть документ, которого нет, а подписанное соглашение создаст
видимость, что он был, и налоговая попросит его показать. В этом случае
прошлое закрывают три документа: п. 1.6 договора № 1547 + акт сверки +
ретро-акт № 3. Если письменный договор был — вписать его номер и дату в
`previous_contract` и перегенерировать.

## Формулировка ретро-акта — почему «разработка», а не «продвижение»

В ретро-периоде (май–июль) сайты Версаля и Венеции ещё только
создавались (venecia-dent.ru задеплоен 29.07.2026). «Продвижение» сайта,
которого не существовало, — проверяемая нестыковка: дата запуска видна по
домену и вебархиву. Поэтому в акте № 3 услуги названы «разработка,
наполнение, запуск и продвижение сайтов Заказчика» — это соответствует
фактам и подкреплено п. 1.3 договора (разработка и доработка сайтов
входят в состав услуг).

## Что закрывает «счетов было больше, чем в договоре»

Три документа работают вместе:

1. **п. 1.6 договора** — условия распространены на отношения, фактически
   возникшие с даты в `contract.retro_from` (п. 2 ст. 425 ГК РФ). Все
   прошлые платежи задним числом получают договорное основание.
2. **Акт сверки взаимных расчётов** — фиксирует, сколько получено и за
   что, и что задолженности нет.
3. **Ретро-акт (№ 3)** — подтверждает, что услуги за этот период
   действительно оказаны и приняты.

Без этой связки прошлые поступления выглядят как оплата без основания —
у клиники их снимут из расходов, а ИП рискует вопросом о безвозмездном
получении. С ней всё сходится: договор → счёт → платёж → акт.

## Режим налогообложения

В документах стоит нейтральное «Без НДС» — как в документах по Сфериксу.
Если ИП на УСН, корректнее писать «НДС не облагается в связи с применением
упрощённой системы налогообложения». Строка задаётся в `build-docs.py`
(поиск по `Без НДС`).
